# Gemini Project Context: Photoblog Israel 2022

This document provides a comprehensive overview of the "Photoblog Israel 2022" project, designed to be used as a context file for AI assistants.

## 1. Project Overview

**Photoblog Israel 2022** is a modern, high-performance, statically-generated website (SSG) that showcases a photography collection from a trip to Israel and Jordan.

The project is built with **SvelteKit 5** (using Runes), styled with **Tailwind CSS v4**, and runs on the **Bun** JavaScript runtime. It uses **Vite** for the build process.

A central and critical part of this project is the **advanced image processing pipeline** located at `scripts/generate-images.ts`. This script uses the **Sharp** library to automatically process original JPEG images into multiple web-optimized formats (AVIF, WebP) and sizes, extracts EXIF metadata, and generates a comprehensive `images.manifest.json` that the SvelteKit application consumes to render the galleries.

### Key Characteristics:

-   **Static Site Generation (SSG):** The entire site is pre-rendered to static HTML, CSS, and JavaScript for maximum performance and SEO, using `@sveltejs/adapter-static`.
-   **Performance-First:** Employs modern image formats, lazy loading, and LQIP (Low-Quality Image Placeholders) for a fast user experience.
-   **Decoupled Content:** Image and text content is stored in the `content/` directory, separate from the application source code in `src/`.
-   **Comprehensive Testing:** The project has a robust testing suite using Vitest for unit/integration tests and Playwright for end-to-end tests. The image generation script itself is heavily tested.
-   **Modern Tooling:** Utilizes Biome for linting and formatting, with pre-commit hooks to ensure code quality.

## 2. Project Structure

The project is organized into three main layers:

1.  **Content Layer (`content/`):**
    -   `content/israel-2022/`: Contains the original high-resolution JPEG photographs.
    -   `content/pages/`, `content/site.md`: Contain Markdown files for textual content, stories, and global site configuration.

2.  **Build-Time Layer (`scripts/`):**
    -   `scripts/generate-images.ts`: The core script that reads from `content/`, processes images, extracts metadata, and produces optimized assets in `static/images/` and the data manifest in `src/lib/images.manifest.json`.

3.  **Application Layer (`src/`):**
    -   This is the SvelteKit application.
    -   `src/routes/`: Defines the page structure and data loading logic. It reads data from the `images.manifest.json` generated by the build script.
    -   `src/lib/components/`: Contains the Svelte components for rendering the UI, such as the photo grid and headers.
    -   `static/`: Contains static assets that are copied directly to the build output, including the generated images.

## 3. Building and Running

All commands are executed using `bun run`.

-   **Development:**
    ```bash
    bun run dev
    ```
    This starts the Vite development server. Note: You may need to run the image generation script separately if you add new images.

-   **Production Build:**
    ```bash
    bun run build
    ```
    This command first runs `lint:ci` and `images:build` (via the `prebuild` script) and then creates a fully optimized, static version of the site in the `build/` directory.

-   **Preview Production Build:**
    ```bash
    bun run preview
    ```
    This serves the contents of the `build/` directory locally.

## 4. Development Conventions

### Image Workflow

The primary development workflow revolves around the image pipeline:

1.  **Add Photos:** Place new original JPEG images into the `content/israel-2022/` directory.
2.  **Generate Assets:** Run the image generation script:
    ```bash
    # To process all new/modified images
    bun run images:build

    # To continuously watch for changes (useful during development)
    bun run images:watch
    ```
3.  The SvelteKit application will automatically pick up the changes from the updated manifest on the next reload.

**Do not manually edit the contents of `static/images/` or `src/lib/images.manifest.json`, as they are auto-generated.**

### Testing

-   **Run all tests:**
    ```bash
    bun run test
    ```
-   **Run only unit tests:**
    ```bash
    bun run test:unit
    ```
-   **Run tests for the image pipeline:**
    ```bash
    bun run test:all
    ```

### Linting and Formatting

The project uses Biome for most linting and formatting, with Stylelint for CSS. Pre-commit hooks are configured to enforce standards automatically.

-   **Check for issues:**
    ```bash
    bun run lint
    ```
-   **Automatically fix and format all files:**
    ```bash
    bun run format
    ```
