# Internationalization (I18N) a lokalizace

Projekt používá **[Paraglide-js](https://inlang.com/m/gerre34r/library-inlang-paraglideJs)** pro správu překladů a lokalizaci.

## Architektura

1.  **Zdrojové soubory**: Nacházejí se v adresáři `messages/` jako JSON soubory (`cs.json`, `en.json`).
2.  **Kompilace**: Paraglide kompiluje JSON soubory do optimalizovaného JavaScriptu v `src/lib/paraglide/`. Tento proces běží automaticky během `vite dev` a `vite build`.
3.  **Runtime**: Používáme `@inlang/paraglide-js` runtime pro přepínání jazyků a získávání aktuálního locale.

## Použití v komponentách

Překlady jsou dostupné přes import `* as m`:

```svelte
<script>
  import * as m from "$lib/paraglide/messages";
</script>

<h1>{m.gallery_title()}</h1>
```

## Pluralizace

Používáme standardní ICU pluralizační pravidla definovaná v `messages/*.json`.
Pro stabilitu SSR existuje **fallback logika** v `src/lib/utils/i18n.ts`, která duplikuje pravidla pro češtinu a angličtinu.

> **Důležité**: Při změně pluralizačních pravidel v JSON souborech je nutné aktualizovat i fallback logiku v `i18n.ts`.

## Dynamické zprávy (Proxy)

V místech, kde potřebujeme přistupovat k překladům dynamicky (např. v modelech nebo s prefixy), používáme `src/lib/utils/messages.ts`:

- `COLLAGE_MESSAGES.TITLE` se automaticky mapuje na `m.collage_title()`.
- Pokud klíč neexistuje:
  - V produkci se vrátí původní řetězec.
  - V development módu se navíc zaloguje varování (`logger.warn`) do konzole a logů.

## Překladové klíče a Typy

Při přidávání nových klíčů do `messages/cs.json` a `messages/en.json` by měl běžící dev server automaticky kompilovat typy.
Pokud IDE nevidí nové klíče, spusťte manuální kompilaci:

```bash
bun x paraglide-js compile --project project.inlang --outdir src/lib/paraglide
```

## Přidání nového jazyka

1.  Vytvořte soubor `messages/<lang>.json`.
2.  Aktualizujte `project.inlang/settings.json` (Paraglide by měl detekovat změny automaticky).
3.  Restartujte dev server.
